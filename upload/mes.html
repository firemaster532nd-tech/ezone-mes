1개발 방향 (Vercel & Supabase 기반)

권장 — 현재 운영 중인 Vercel 배포 시스템 및 Supabase(PostgreSQL 클라우드) 환경을 기준 시스템(System of Record)으로 확정하여 고도화를 진행한다. 이미 완성도 높은 클라우드 인프라가 확보되어 있으므로 불필요한 이전 공수 없이, 입력검증 5종·이상치 보고·정합성 대시보드 추가에 개발력을 집중한다.
근거내용
①현 Vercel + Supabase v1 환경에 검사 4단계·LOT 계보·수불·결재가 구현되어 있어, 부족한 것은 인프라 변경이 아닌 실시간 데이터 무결성을 보장하는 검증 계층(Validation Layer)이다.
②Supabase는 강력한 PostgreSQL 제약조건(Constraints) 및 RLS(Row Level Security)를 제공하므로, 클라이언트 우회 입력 차단 및 데이터 잠금 처리를 가장 높은 보안 수준으로 바로 적용 가능하다.
③Vercel Serverless/Edge Functions를 이용해 API 응답 속도를 최적화하고 현장의 다양한 기기(태블릿, 모바일)에 신속한 검증 피드백을 전달할 수 있다.

2AI(Claude Code) 코딩 백로그 — 스프린트별

작업 단위는 "1작업 = 1기능 = 1커밋 + 테스트"를 원칙으로 한다. Supabase의 스키마 정의 및 Vercel Route Handlers에 특화된 프롬프트 작성을 위해 프로젝트 루트의 CLAUDE.md·DESIGN_GUIDE.md를 활용한다.

No작업구현 내용

1-2Vercel Serverless 검증 미들웨어데이터 저장 API(Next.js Route Handler / Express Route)에서 입력 형식(자릿수)·범위·반복값(n1=n2=n3)·필수값 검증. 범위 이탈 시 409 OUT_OF_RANGE 응답 → 사유 포함 재요청 시에만 is_outlier=true로 저장

# Claude Code 프롬프트 예시 (작업 1-2: Next.js API Routes / Vercel Serverless 환경)
app/api/inspections/route.ts 에 Supabase DB와 연동된 서버측 검증 로직을 추가해줘.

규칙:
1. supabase client를 이용해 inspection_criteria 테이블에서 항목별 min/max/decimal_places/is_required 를 조회
2. 소수 자릿수 초과 → 400 INVALID_PRECISION 반환
3. 필수값(LOT 포함) 누락 → 400 MISSING_REQUIRED 반환
4. n1=n2=n3 완전 동일 → 응답에 warning: REPEATED_VALUE 포함 (저장은 허용)
5. min/max 이탈 → outlier_reason 없으면 409 OUT_OF_RANGE 반환,
   outlier_reason 있으면 is_outlier=true 로 저장하고, Supabase의 트랜잭션(or RPC)을 사용하여 approvals 테이블에 품질책임자 결재 레코드를 생성

검증 로직은 유틸리티 함수로 분리하고, 경계값 테스트(4.74/4.75/5.25/5.26, 사유 유무) 코드를 작성해줘.

5관리자 정합성 검토 체계

개인 입력의 정합성은 "작업자 입력 → 시스템 자동 체크 → 관리자 일일 확인 → 주간 확정(잠금)"의 4겹으로 관리한다. 관리자는 개별 값을 다시 재는 것이 아니라 시스템이 걸러낸 예외만 검토한다.
