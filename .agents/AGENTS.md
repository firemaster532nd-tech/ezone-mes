## 1. 개발 방향 원칙

- 현재 운영 중인 **Vercel + Supabase(PostgreSQL) 환경을 기준 시스템으로 확정**하여 고도화를 진행한다.
- 불필요한 인프라 이전 없이 **입력검증 5종 · 이상치 보고 · 정합성 대시보드** 추가에 개발력을 집중한다.
- 클라이언트 우회 입력 차단은 **Supabase Constraints + RLS**로 DB 수준에서 원천 차단한다.
- API 응답 속도 최적화는 **Vercel Serverless/Edge Functions**를 활용한다.

## 3. AI 코딩 산출물 QA 절차

코드 변경은 반드시 아래 4단계를 거쳐야 반영한다:

```
① 생성 → ② diff 검토 (Vercel 빌드 영향도 + Supabase 스키마 영향 분석)
        → ③ 자동 테스트 (Edge 환경 호환성, 경계값·필수값 테스트)
        → ④ 시나리오 검증 (실데이터 체크 통과 시 Production 배포)
```

### 경계값 테스트 기준 (예: 두께 4.75~5.25mm)

| 입력 | 기대 동작 | 판정 |
|------|----------|------|
| 5.02 (범위 내) | 정상 저장 | OK |
| 4.75 / 5.25 (경계) | 정상 저장 (경계 포함) | OK |
| 4.74 / 5.26 (이탈) | 경고 + 사유 없으면 저장 거부 | WARN |
| 이탈값 + 사유 입력 | `is_outlier=true` 저장 + 보고 생성 | REPORT |
| 5.023 (자릿수 초과) | 입력 차단 또는 형식 오류 | BLOCK |
| n1=n2=n3 동일 | 반복값 경고 표시 (저장 허용) | WARN |
| LOT 미입력 | 저장 차단 (MISSING_REQUIRED) | BLOCK |

### 기능 완료 판정 체크리스트

- [ ] Vercel edge/node 서버 및 프론트 양쪽 검증 동작 (클라이언트 변조도 DB Constraints 차단)
- [ ] 이상치 저장 시 보고·결재 트랜잭션이 Supabase 내 단일 트랜잭션으로 완료
- [ ] RLS 정책 활성화 — 비로그인 및 권한 밖 사용자의 직접 수정 차단
- [ ] 역추적 화면에서 LOT 계보 정보가 깨짐 없이 실시간 연결
- [ ] Vercel Production Build 시 타입·린트 오류 없음, 기존 기능 회귀 없음

## 4. 공정별 개인 입력 책임 매트릭스

> **입력 원칙**: 공정 종료 즉시, 해당 작업자가, 본인 계정으로 입력 (로그인 계정 = 서명, 대리입력 금지)

| 공정 | 입력자 | 필수 입력 항목 | 자동 검증 (시스템) |
|------|-------|--------------|-----------------|
| 인수검사 | 김정용 책임 | 입고 LOT(자동채번), 밀시트 LOT 매칭, n1/n2/n3 실측값, 판정 | 범위검증(팽창률 ≥250 등), 반복값 감지, 매칭 불가 시 입고 차단 |
| 배합(MIX) | 공정 작업자 | 배합 LOT, 투입 원료 LOT, 실측 중량(kg), 시작/종료 시각 | 중량 필수화, 투입 LOT 유효성(검사 합격 LOT만 선택 가능) |
| 압출(EXT) | 공정 작업자 | 배합 LOT 상속 확인, 투입량 실측, 중간검사 시편 측정값 | C-701 기준 범위검증, KG→M 환산 자동 계산 |
| 재단(CUT) | 공정 작업자 | 투입 생산 LOT / 세라믹울 LOT(필수), 치수 실측(버니어 소수 2자리) | LOT 미입력 저장 차단, 자릿수 고정 |
| 조립(ASM) | 공정 작업자 | 구성자재 LOT(소켓/시트/차열재/실란트) + 글라스울 LOT(필수), 구조명, J-LOT(자동채번) | 구성 LOT 전체 필수화, 구조명 필수, 계보 자동 기록 |
| 출하(SHP) | 김봉민 책임 | 출하 LOT 연결, 최종검사 결과, 품질관리서 발행 | 미검사 LOT 출하 차단, C-304 출하지시서 연동 |

## 5. 관리자 정합성 검토 체계

### 자동 정합성 체크 4종 (Supabase SQL 기반 상시 실행)

| 코드 | 체크 | 내용 | 예외 발생 시 |
|------|------|------|------------|
| C1 | LOT 연결성 | 완제품 LOT 역추적 시 원재료까지 경로 단절 여부 (계보 gap 탐지) | 끊김 LOT 목록 표시 → 해당 공정 입력 보완 지시 |
| C2 | 수불 대사 | 공정 투입량 합계 vs 재고 출고 기록 vs BOM 소요량(로스율 포함) | 편차 초과 건 → 로스 기록 확인 또는 재고 조정 결재 |
| C3 | 검사 누락 | 완료된 작업지시 중 대응 검사기록(인수/중간/자주) 없는 건 | 미검사 건 → 검사 소급 불가 원칙, 즉시 검사 지시 |
| C4 | 입력 시점·이상치 | 공정 종료 후 미입력·지연 입력 건수, 이상치 보고 미처리 건 | 지연 상습 공정 → 원인 파악(입력 환경/교육) |

### 관리자 검토 루틴

| 주기 | 담당 | 수행 내용 |
|------|------|---------|
| 일 1회 (익일 오전) | 공정관리자 (임병용 파트장) | C1~C4 예외 확인 → 건별 조치. 예외 0건이면 당일분 확인 처리 |
| 수시 | 품질책임자 (최진영 책임) | 이상치 보고 결재함 처리 — 판정 3분기(재검사/오기 정정/부적합 확정→CAR) |
| 주 1회 | PM (이동민 파트장) | 주간 확정(잠금): 예외 미해결 이월, 이상치·로스 추이 검토 |
| 월 1회 | PM + 품질 | 월마감 + LOT 추적 샘플링 감사 — 임의 완제품 LOT 2~3건 역추적 |

### 불변 원칙 (공장심사 신뢰성 기준)

1. 확정(잠금)된 기록은 수정 불가 — 정정은 원본 보존 + 사유 이력으로만
2. 이상치는 삭제·수정 대상이 아니라 보고·판정 대상
3. 검사 소급 입력 금지

## 6. 권한·역할 매핑 및 운영 원칙

| 권한 | 대상 | 가능 작업 | 불가 작업 |
|------|------|---------|---------|
| worker | 공정 작업자 | 본인 공정 입력(작업지시 실행, 검사값, LOT), 본인 입력분 당일 수정 | 타 공정 입력, 확정 기록 수정, 기준값 변경 |
| manager | 임병용·최진영·김정용·김봉민 책임 | 예외 조치, 이상치 판정 결재, 일일 확인, 재고 조정 승인 | 검사기준(min/max) 변경, 감사 로그 삭제 |
| admin | 이동민 파트장 (+시스템 담당) | 기준값 관리(개정 이력), 주간 확정·잠금, 사용자·백업 관리 | 확정 기록의 이력 없는 수정 (시스템상 불가) |

- 검사기준(min/max·자릿수)은 admin 역할만 Update 가능하도록 Supabase RLS Policy 설정
- 변경 내역은 DB 트리거로 감사 테이블에 이력 보존 (기준 무단 완화 방지)
- 이카운트 연동(중기 과제) — 작업지시·재고 이중입력 제거 시 C2 비교 기준이 ERP로 일원화
- 교육 — 적용 첫 주는 경고를 "차단"이 아닌 "안내" 모드로 운영, 현장 적응 후 강제 전환 권장
